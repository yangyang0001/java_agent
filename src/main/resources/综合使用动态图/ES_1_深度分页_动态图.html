深度分页：from + size 为什么越翻越慢，10000 从哪来

ES 查询分 Query 和 Fetch 两个阶段。用 from + size 翻页时，每个分片都要排序并返回前 from + size 条，协调节点要合并 分片数 × (from + size) 条，最后只留下 size 条。页越深开销越大，所以 from + size 超过 index.max_result_window（默认 10000）直接报错。search_after 每页的开销固定。

query_then_fetch：1 个协调节点 + 5 个主分片

Query 阶段返回的条数 开销很大 Fetch 阶段 / 正常 报错

柱高按条数线性绘制：第 1~100 页时柱子几乎看不见，到第 1000 页才"突然"变满，这正是开销随页深线性增长的样子。
