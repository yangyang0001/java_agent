指令重排：双重检查锁（DCL）单例为什么要加 volatile

为了提高性能，编译器和 CPU 会在不改变单线程结果的前提下调整指令顺序。instance = new Singleton() 分三步：分配内存、初始化对象、引用指向内存。后两步可能被重排，另一个线程就会拿到一个还没初始化完成的对象。

    要点
    
    
      
      
    • 指令重排：为了提高性能，在不改变单线程执行结果的前提下，改变指令的执行顺序。
      • 
      
    • 三个来源：编译器优化重排 → 处理器指令级并行重排 → 内存系统重排（Store Buffer 导致看起来乱序）。
      • 
      
    • 单线程遵守 as-if-serial 语义，有数据依赖的指令不会重排；但多线程下会出问题。
      • 
      
    • DCL 单例：instance = new Singleton() 分 3 步（1 分配内存、2 初始化对象、3 引用指向内存），2 和 3 可能被重排成 1 → 3 → 2，另一个线程在第一次判断时看到 instance != null，拿到的却是没初始化完成的对象。
      • 
      
    • 解决：instance 加 volatile。volatile 写前面的 StoreStore 屏障保证初始化先于引用发布；读线程的 volatile 读之后有 LoadLoad / LoadStore。（JDK5 / JSR-133 之后 volatile 才有这个语义。）
      • 
      
    • 禁止重排的手段：volatile、synchronized、final（构造函数内的 final 字段写不会逸出）、Unsafe / VarHandle 的屏障方法。
