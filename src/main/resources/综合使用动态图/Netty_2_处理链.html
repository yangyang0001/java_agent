    跳过判断：executionMask 位掩码
    依据 netty-transport 4.1.113.Final 源码：ChannelHandlerMask、AbstractChannelHandlerContext
    

    Netty 不在传播时做 instanceof。每个 Handler 在 addLast 创建 Context 时算出一个 int executionMask，每种事件占 1 位；传播时沿 next / prev 查找，用一次 & 判断是否跳过。例：OutboundA 只有 write 位，入站 channelRead 时被跳过。

    一句话：ONLY_* 只含本方向的 8 位（用来判断方向）；ALL_* = ONLY_* 再加 bit0 exceptionCaught（用来初始化）。入站占低位 bit1~8，出站占高位 bit9~16，两组完全不重叠，所以 MASK_ONLY_INBOUND & MASK_ONLY_OUTBOUND = 0。bit 编号从第 0 位开始（最右边是 bit0）：bitN 就是 1<<N，bit0 = 1 = exceptionCaught，bit16 = 65536 = flush。
    

    为什么分 ONLY / ALL：区别只在 exceptionCaught（bit0）。两个方向的 Handler 都可能重写 exceptionCaught，所以初始化用 ALL 要包含它；判断方向时要排除它，否则重写了 exceptionCaught 的 Outbound 会让“该方向一个位都没有”的判断失效。
    

    按位或（|）：任一方为 1 结果就为 1；各位互不重叠，所以 | 等于相加。点开查看每个组合掩码的计算过程。

    ③ mask0() 计算过程（ChannelHandlerMask L91）
    

    1. 初始 mask = MASK_EXCEPTION_CAUGHT (1)。
    2. 实现 ChannelInboundHandler：mask |= MASK_ALL_INBOUND (511)，再逐个检查 8 个入站方法。
    3. 实现 ChannelOutboundHandler：mask |= MASK_ALL_OUTBOUND (130561)，再逐个检查 8 个出站方法。
    4. 最后检查 exceptionCaught。
    

    检查方式 isSkippable：handlerType.getMethod(方法名, 参数类型) 拿到实际生效的 public 方法（子类重写的优先），看它有没有 @Skip。Adapter 的默认方法都标了 @Skip；子类重写后的新方法没有（方法注解不继承）。有 @Skip 就 mask &= ~该位 清 0，没有就保留。|= X 把 X 中为 1 的位置 1；&= ~X 先把 X 取反（只有该位为 0），再按位与，只清掉该位。

    ⑤ 跳过判断源码（AbstractChannelHandlerContext L1068~1095）
    

    private AbstractChannelHandlerContext findContextInbound(int mask) {     // 入站: 沿 next 往后    AbstractChannelHandlerContext ctx = this;    EventExecutor currentExecutor = executor();    do {        ctx = ctx.next;    } while (skipContext(ctx, currentExecutor, mask, MASK_ONLY_INBOUND));    return ctx;}// findContextOutbound 完全对称: ctx = ctx.prev, onlyMask 换成 MASK_ONLY_OUTBOUNDprivate static boolean skipContext(AbstractChannelHandlerContext ctx, EventExecutor currentExecutor,                                   int mask, int onlyMask) {                 // 返回 true = 跳过    return (ctx.executionMask & (onlyMask | mask)) == 0 ||                    // ① 该方向一个位都没有 → 必跳           (ctx.executor() == currentExecutor && (ctx.executionMask & mask) == 0); // ② 同线程且没重写该方法 → 跳}
    

    • 条件一：纯 Outbound Handler 在入站时无条件跳过；反之，纯 Inbound Handler 在出站时无条件跳过。OutboundA 就是这样被跳过的。
    • 条件二：同方向但没重写当前方法（如 Inbound 没重写 channelRead）也跳过；但若它绑定了别的 executor（addLast(group, name, handler)）就不能跳，必须提交到它的线程，由 Adapter 默认方法转发，保证事件顺序（netty #10067）。
    • 调用方：fireChannelRead → findContextInbound(MASK_CHANNEL_READ)（L412）；write / writeAndFlush → findContextOutbound(flush ? MASK_WRITE | MASK_FLUSH : MASK_WRITE)（L976）。
    • 循环不判 null：Head / Tail 是哨兵，各自方向位齐全，查找一定停在它们身上。
    

    示例：inboundA.fireChannelRead("hello")，mask = MASK_CHANNEL_READ (0x20)，onlyMask = MASK_ONLY_INBOUND (0x1FE)
