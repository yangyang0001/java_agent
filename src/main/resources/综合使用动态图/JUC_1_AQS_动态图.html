AQS：state + 双向等待队列 + park / unpark

AbstractQueuedSynchronizer 是 ReentrantLock、Semaphore、CountDownLatch 等的底层框架。它用 volatile int state 表示同步状态，用 CAS 修改；获取失败的线程封装成 Node 进入 CLH 变体的双向队列，然后 LockSupport.park 挂起；释放时唤醒 head 的后继。子类只需要定义 state 的含义。

同步状态与等待队列

持有锁 / 获取成功 park 挂起 / SIGNAL 当前动作 获取失败

队列节点上方的 head / tail 是 AQS 的两个指针；节点之间上面的箭头是 next，下面的箭头是 prev。head 永远是一个不关联线程的哑节点，代表"当前持有锁的那个位置"。

    要点
    
    
      
      
    • 核心三要素：volatile int state（重入次数 / 许可数 / 计数器，CAS 修改）；CLH 变体的 FIFO 双向等待队列（失败线程封装成 Node 入队并 park）；模板方法模式（AQS 管排队、阻塞、唤醒，子类只定义怎么算获取成功）。
      • 
      
    • 两种模式：独占 EXCLUSIVE（ReentrantLock），共享 SHARED（Semaphore、CountDownLatch）。共享模式唤醒会沿队列传播。
      • 
      
    • 子类重写的钩子：tryAcquire / tryRelease、tryAcquireShared / tryReleaseShared、isHeldExclusively；状态操作：getState / setState / compareAndSetState。
      • 
      
    • 对外模板方法：acquire、acquireInterruptibly、tryAcquireNanos、release 及对应的 Shared 版本；hasQueuedPredecessors（公平锁用）、hasQueuedThreads、getQueueLength。
      • 
      
    • Node.waitStatus：CANCELLED(1)、SIGNAL(-1)、CONDITION(-2)、PROPAGATE(-3)、0。内部类 ConditionObject 维护单向条件队列，signal 时把节点转移到同步队列。
      • 
    
    
    
    
      
    
        
    内部方法作用
    
        
          
    addWaiter把当前线程封装成 Node，CAS 加到队尾
    
          
    enq自旋 + CAS 入队；队列为空时先初始化 head 哑节点
    
          
    acquireQueued在队列中自旋：前驱是 head 就 tryAcquire，否则判断是否 park
    
          
    shouldParkAfterFailedAcquire把前驱的 waitStatus 设为 SIGNAL(-1)，跳过 CANCELLED 节点
    
          
    parkAndCheckInterruptLockSupport.park 挂起，醒来后返回中断标记
    
          
    unparkSuccessor释放时唤醒后继；后继为空或已取消时从 tail 往前找
    
          
    cancelAcquire取消节点（超时 / 中断）
