间隙锁：锁住记录之间的空隙，防止插入

间隙锁（Gap Lock）锁住索引记录之间的开区间，不让别的事务往里插入数据，用来在 RR 隔离级别下解决当前读的幻读。Next-Key Lock = 记录锁 + 间隙锁，是左开右闭区间，是 InnoDB 在 RR 下加锁的基本单位。

主键索引 t(id) 上的记录与间隙

事务 A 持有的锁 事务 B 持有的锁 等待中 冲突 / 死锁 插入成功

数轴上方是事务 A 的锁，下方是事务 B 的锁。加锁规则以 MySQL 8.0 之前的经典总结为准，不同小版本在边界上略有差异。

    产生间隙锁的情况（前提：RR + 当前读）锁住什么
    
        
          
    范围查询，如 id > 10 AND id < 20范围内的记录和间隙
    
          
    非唯一索引的等值查询命中记录前后的间隙（防止插入相同值）
    
          
    唯一索引的等值查询，但记录不存在退化为该值所在的间隙锁
    
          
    查询条件没有用到索引全表扫描，所有记录和间隙都被锁住，相当于锁表
    
            
      
    
    
    
    
      
      
    • 当前读：SELECT ... FOR UPDATE / LOCK IN SHARE MODE、UPDATE、DELETE。唯一索引等值查询且记录存在时，Next-Key Lock 退化为记录锁。
      • 
      
    • 加锁规则：基本单位是 Next-Key Lock（左开右闭）；查找过程中访问到的对象才加锁；唯一索引等值命中退化为记录锁；等值查询向右遍历到最后一个不满足条件的值时退化为间隙锁。
      • 
      
    • 间隙锁之间不冲突，只和插入意向锁冲突，所以“先查后插”容易死锁。
      • 
      
    • 如何避免：用 RC 隔离级别（配合 binlog_format=ROW）；尽量用主键 / 唯一索引等值命中已有记录；确保走索引；缩小范围；用唯一索引 + INSERT ... ON DUPLICATE KEY UPDATE 或 INSERT IGNORE 代替“先 FOR UPDATE 再 INSERT”；事务尽量短。
