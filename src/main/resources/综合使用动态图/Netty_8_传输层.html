传输层（NIO、Epoll 与零拷贝）

NIO 与 native Epoll 是不同传输实现，业务 Pipeline 可以保持相同。零拷贝则是减少特定环节的数据复制：共享 ByteBuf 视图、组合缓冲和文件传输优化作用在不同层面，不能等同于“整个请求完全不拷贝”。

    最小知识单元
    概念落地边界
    NIO / native Epoll跨平台 JDK 通道与 Linux native 传输；Group 和 Channel 实现必须匹配。
    

    ByteBuf 级减少复制slice / duplicate 共享存储；CompositeByteBuf 组合组件而非预先拼接。
    

    文件传输级减少复制FileRegion 适用于合适文件传输路径；标准 TLS 加密会改变数据路径。
    

    常见问题与排查
    现象先检查什么 / 如何处理
    UnsatisfiedLinkError检查 native classifier、操作系统、CPU、libc 与依赖版本；记录不可用原因。
    

    Channel 注册失败检查 Epoll / NIO 的 EventLoopGroup 与 Channel 是否配套。
    

    换 Epoll 性能没提升先测吞吐、尾延迟、CPU 与业务等待；收益依赖实际瓶颈。
    

    TLS 下文件发送失败检查 SslHandler 支持的消息类型，采用能进入加密路径的分块方案。
