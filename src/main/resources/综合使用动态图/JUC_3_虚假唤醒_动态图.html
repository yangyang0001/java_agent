JUC · 3 · Spurious Wakeup

虚假唤醒：为什么 wait 必须写在 while 里

线程从 wait() / Condition.await() 中醒来，但它等待的条件其实并不满足，这就是虚假唤醒。原因有两类：notifyAll 唤醒了多个线程，条件被第一个线程消费掉了；或者操作系统层面 pthread_cond_wait 在没有 notify 的情况下返回。解决办法只有一个：醒来后用 while 重新检查条件。

对象监视器：持锁者、WaitSet、EntryList

正常完成 wait 中 持锁执行 / 被唤醒 出错 队列元素 / 虚假唤醒

wait() 会释放锁并进入 WaitSet；notifyAll() 把 WaitSet 中的线程移到 EntryList，它们要等持锁线程退出同步块后重新抢锁，抢到后从 wait() 的下一行继续执行。

    • 原因一（操作系统层面）：pthread_cond_wait 等底层实现允许在没有 notify 的情况下返回（POSIX 规范允许）。

    • 原因二（业务层面）：notifyAll 唤醒了多个线程，条件被第一个线程消费掉了，其余线程醒来时条件已不成立。
      • 
      
    • 解决：条件判断必须用 while 而不是 if，醒来后重新检查条件：
        
      synchronized (lock) {    while (!condition) {        lock.wait();    }    // 处理业务}
