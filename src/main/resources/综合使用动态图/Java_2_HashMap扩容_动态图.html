HashMap 扩容：16 → 32，每个桶拆成高低两条链

JDK8 的 HashMap 是数组 + 链表 + 红黑树。hash = h ^ (h >>> 16)，下标 (n - 1) & hash。size > threshold 时容量翻倍；扩容时按 hash & oldCap 把每个桶拆成两条链：低位链留在 j，高位链移到 j + oldCap，尾插保持顺序。

table 数组与桶中的链表

本步写入 低位链（留在 j） 高位链（去 j + oldCap）/ TreeNode 触发扩容

key 都用 Integer：它的 hashCode() 就是数值本身，方便心算下标。格子里的小字是桶下标。

    • 结构（JDK8）：Node[] table + 链表 + 红黑树。hash = h ^ (h >>> 16) 让高 16 位参与运算、减少碰撞；下标 (n - 1) & hash。
      • 
      
    • 链表长度 ≥ 8（TREEIFY_THRESHOLD）且数组长度 ≥ 64（MIN_TREEIFY_CAPACITY）时转红黑树；数组长度 < 64 时优先扩容；树节点 ≤ 6（UNTREEIFY_THRESHOLD）时退化回链表。
      • 
      
    • 初始化：默认容量 16、负载因子 0.75、阈值 12；构造时不建数组，第一次 put 才 resize()；指定容量会被 tableSizeFor 向上取到 2 的幂（10 → 16）。
      • 
      
    • 容量必须是 2 的幂：才能用 (n - 1) & hash 代替取模，扩容时新位置也能快速算出。
      • 
      
    • 扩容：size > threshold 时容量和阈值都翻倍；按 hash & oldCap 拆成高低两条链，== 0 留在 j，!= 0 移到 j + oldCap；不重新计算 hash，尾插保持顺序。
      • 
      
    • JDK7：数组 + 链表、头插法、扩容时逐个重新计算下标；并发扩容时头插会反转链表，可能形成环 → get 死循环。JDK8 改尾插解决了死循环，但 HashMap 仍非线程安全（并发 put 会丢数据），并发场景用 ConcurrentHashMap。
      • 
      
    • 对比：Hashtable 默认 11、扩容 2n + 1；ConcurrentHashMap（JDK8）用 CAS + synchronized 锁桶头节点，支持多线程协助扩容。
