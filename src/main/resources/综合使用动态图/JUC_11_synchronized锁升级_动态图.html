synchronized 锁升级：Mark Word 怎么变

synchronized 代码块编译为 monitorenter / monitorexit，方法用 ACC_SYNCHRONIZED 标志；锁状态记录在对象头的 Mark Word 中。随着竞争加剧，锁按 无锁 → 偏向锁 → 轻量级锁 → 重量级锁 升级，一般不降级。

    • 出现其他线程竞争时，偏向锁要在安全点撤销，再升级为轻量级锁。调用过 hashCode() 的对象无法偏向：Mark Word 没有位置同时存线程 ID 和 hashCode。
      • 
      
    • 版本变化：JDK15（JEP 374）默认禁用偏向锁并标记为废弃（撤销成本高，现代应用收益小），后续版本已移除，所以新版本 JDK 中实际是 无锁 → 轻量级锁 → 重量级锁。
      • 
      
    • 其他优化：锁消除（逃逸分析发现对象不会逃逸）、锁粗化（合并相邻的同步块）。
      • 
      
    • 本图按经典实现讲解。较新的 JDK 还引入了基于 lock-stack 的新轻量级锁实现，不再复制 Displaced Mark Word，但“轻量级 → 重量级”的思路不变。
