一致性哈希环、虚拟节点与 Redis Cluster 哈希槽

一致性哈希把 0 ~ 2³²-1 的哈希空间首尾相连成一个环，节点和 key 都映射到环上，key 沿顺时针找到的第一个节点就是它的归属。增减节点时只影响环上相邻的一段数据。Redis Cluster 并没有用它，而是用 16384 个哈希槽。

    方案映射方式增减节点时问题与对策
    
        
          
    普通取模hash(key) % NN 一变，几乎所有 key 都要迁移不适合需要扩缩容的场景
    
          
    一致性哈希0 ~ 2³²-1 成环，key 顺时针找第一个节点只影响环上相邻的一段数据节点少时数据倾斜，宕机时数据全部压到下一个节点 → 虚拟节点（如每个物理节点 150 个）
    
          
    Redis Cluster 哈希槽slot = CRC16(key) % 16384，每个主节点负责一部分槽扩缩容 = 迁移槽，可以手动控制多 key 命令、事务、Lua 要求在同一个槽 → 用 {hash tag}
    
            
      
    
    
    
    
      
      
    • 为什么是 16384：节点间心跳包用 bitmap 携带槽信息，16384 位 = 2KB，大小合适；官方建议集群节点不超过 1000 个，16384 个槽足够。
      • 
      
    • 一致性哈希的使用场景：客户端分片（Jedis ShardedJedis）、代理分片（Twemproxy 的 ketama）。
